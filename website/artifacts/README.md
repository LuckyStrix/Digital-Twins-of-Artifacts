# Artifact folder format

Each artifact gets its own subfolder in here. The modeling pipeline (or
you, by hand) should create one folder per artifact containing exactly:

- one model file — any of:
  - a `.glb` (preferred — everything packed into one file)
  - a loose `.gltf`, plus whatever `.bin`/texture files it references
  - a `.obj`, plus its companion `.mtl` (and textures) if it has one —
    OBJ has no materials of its own, so without a `.mtl` it loads with
    a flat default material instead of its real look
  - or, for an artifact scanned from both sides, **two** `.glb` files —
    see "Two-sided artifacts" below
- one `.txt` file — metadata, in this format:

```
Name: Cuneiform Tablet 12
Type: tablet
Description: A clay tablet bearing an
administrative record from the
Third Dynasty of Ur.
Link: https://example.edu/collection/tablet-12
Link Label: Cary Collection Link
```

Notes on the `.txt` format:

- `Link` and `Link Label` are both optional. If `Link` is present, the
  viewer shows a button in the info panel that opens that URL in a new
  tab, labeled with `Link Label` (or "View Source" if omitted).

- Field order doesn't matter, and field names are case-insensitive.
- `Description:` captures everything after it through the end of the
  file. A blank line starts a new paragraph; single line breaks within
  a paragraph are treated as soft wraps and collapsed into one line.
- `Type` is freeform (e.g. `tablet`, `scroll`, `papyrus`, `other`) —
  the homepage groups artifacts by whatever value you put here.
- Folder names become the artifact's URL id, so keep them simple
  (letters, numbers, hyphens).

The folder name itself doesn't need to match the artifact name — only
the contents of the `.txt` file are shown on the site.

## Adding a new artifact

1. Create a new folder in `artifacts/` (e.g. `artifacts/tablet-014/`).
2. Drop in the model file (`.glb`, or `.gltf`/`.obj` with their
   companion files) and an `info.txt`. Any filename ending in `.txt`
   works for the metadata file.
3. From the `fully_rewritten/` folder, run:

   ```
   python3 tools/build_manifest.py
   ```

4. Reload `index.html` — the new artifact appears in its type group
   automatically, no HTML edits required.

`manifest.json` in this folder is generated by that script — don't
edit it by hand, it gets overwritten every time you rebuild.

## Two-sided artifacts

A papyrus scanned front and back goes in **one** folder with **two**
`.glb` files. The viewer shows it as a single artifact with a "Flip to
other side" button that turns the sheet over.

```
artifacts/papyrus-014/
  side1.glb    <- front: shown first
  side2.glb    <- back: shown after flipping
  info.txt
```

The alphabetically-first `.glb` is the front, so name the pair in the
order you want them seen. The 2D capture pipeline's "Scan both sides"
option writes `side1/model/render.glb` and `side2/model/render.glb` —
copy those in as `side1.glb` and `side2.glb`.

This applies to exactly two `.glb` files. A folder with three or more,
or with a loose `.gltf`/`.obj`, still resolves to a single model — the
companion `.bin`/`.mtl` files of those formats can't be distinguished
from a second side. Both sides must be `.glb`.

## `msi/` — data from the external MISHA system

An artifact folder may also contain an `msi/` subfolder holding
multispectral band data. **This data comes from MISHA (Multispectral
Imaging System for Historical Artifacts), an independent project at RIT's
Cultural Heritage Imaging, Preservation, and Research program
(https://www.rit.edu/chipr/misha) — it is not one of this repo's own
2D/3D capture systems.** Artifacts with `msi/` data show up in the
homepage's separate "MISHA-Imaged Artifacts" section, not the regular
type-grouped gallery, and link to `msi.html` instead of `viewer.html`. An
artifact can have `msi/` data with no 3D model at all (e.g. `ege-30`).

```
artifacts/<id>/msi/
  bands/<wavelength>nm.webp   one downsampled, contrast-stretched image
                               per captured wavelength
  msi_manifest.json           band list + wavelengths — machine-written by
                               tools/build_msi_assets.py, never hand-edit
  recipes.json                optional, hand-authored curator presets (band
                               weights + exposure/contrast) for the web
                               equalizer viewer — build_msi_assets.py never
                               touches this file
```

To add MISHA data for an artifact, see "Adding MISHA multispectral data"
in [`../README.md`](../README.md).
